# Инструкция по эксплуатации RunPod

Актуальность: 5 октября 2026 года.

Для постоянной работы использовать схему из
[настроек повторного запуска](RUNPOD_TEMPLATE_RU.md): свой шаблон и Network Volume.
Исторический тест с обычным Volume Disk описан ниже для справки.

## Запуск нового Pod

1. Выбрать GPU под конкретный workflow.
2. Выбрать шаблон Timesaver ComfyUI Docker.
3. Указать образ:

   ```text
   ghcr.io/alexyez/timesaver-comfyui-docker:cu128-20261005
   ```

   Для проверки самой свежей сборки использовать `:cu128`.

4. Оставить HTTP-порт `8188` с меткой `ComfyUI`.
5. Выделить Container Disk не меньше 40 ГБ; рекомендуемый размер — 50 ГБ.
6. Для постоянной работы подключить свой Network Volume при размещении Pod.
   Обычный Volume Disk подходит для короткого теста, но удаляется с Pod.
7. Нажать Deploy On-Demand.

Первый старт включает скачивание Docker-образа размером около 10,61 ГиБ. Порт некоторое время может показывать `Initializing`.

## Признаки успешного запуска

Во вкладке Connect должен появиться HTTP Service на порту 8188 со статусом Ready. В конце лога ожидаются сообщения о запуске сервера и адресе `0.0.0.0:8188`.

Проверить системное состояние можно по адресу:

```text
https://<POD_PROXY_HOST>/system_stats
```

Список загруженных классов нод доступен здесь:

```text
https://<POD_PROXY_HOST>/object_info
```

## Проверка нод

1. Обновить страницу сочетанием `Ctrl+Shift+R`.
2. Дважды щёлкнуть по пустому месту графа.
3. Ввести `TS_`.
4. Для CosyVoice проверить `TS_CosyVoice3_ModelLoader`.

Встроенные ноды могут не отображаться в Manager как Installed, хотя ComfyUI уже загрузил их. Не устанавливать повторно три встроенных пака без предварительного изменения схемы Docker.

## Где лежат данные

```text
/workspace/models       модели
/workspace/input        исходные файлы
/workspace/output       результаты
/workspace/user         настройки и workflow пользователя
/workspace/custom_nodes дополнительные ноды
/workspace/.cache/pip   кэш Python-пакетов
```

## Stop и Terminate

### Stop

- прекращает оплату GPU;
- очищает Container Disk;
- сохраняет обычный Volume Disk;
- Volume Disk продолжает тарифицироваться как остановленный.

После нового старта Docker-окружение восстанавливается из GHCR, а `/workspace` подключается снова.

### Terminate

- удаляет Pod;
- удаляет связанный с ним обычный Volume Disk;
- не затрагивает независимый Network Volume или внешнее Object Storage.

До настройки резервной копии не нажимать Terminate, если в `/workspace` лежат единственные экземпляры моделей, workflow или результатов.

## Обновление

### ComfyUI и три встроенных пака

ComfyUI обновляется при еженедельной сборке образа и после изменения проекта.
Чтобы применить обновление, создать новый Pod с тегом `cu128` или новой проверенной
версией. В новом entrypoint TS-паки копируются только при отсутствии на диске.
Существующие паки обновлять через Manager: пересоздание Pod их не перезаписывает.

### Дополнительные ноды

Открыть Manager, проверить обновления и нажать Update. Перед массовым обновлением сохранить workflow и рабочее состояние.

### Откат

Если свежий образ не запускается или ломает workflow, вернуться на проверенный датированный тег:

```text
ghcr.io/alexyez/timesaver-comfyui-docker:cu128-20260830
```

## Что делать при проблемах

### Порт Ready, но страница не открывается

1. Скопировать proxy-адрес вручную в новую вкладку.
2. Нажать `Ctrl+Shift+R`.
3. Временно отключить блокировщик для `proxy.runpod.net`.
4. Проверить `/system_stats`.

### Нода отсутствует в поиске

1. Проверить её имя через `/object_info`.
2. Открыть Logs и найти `IMPORT FAILED` или traceback.
3. Проверить наличие каталога в `/workspace/custom_nodes`.
4. Проверить зависимости в `requirements.txt`.

### Модель скачивается медленно

1. Не включать Global Networking ради ускорения интернета.
2. После текущей загрузки измерить скорость до Hugging Face.
3. Проверить версию `huggingface_hub` и наличие `hf_xet`.
4. При следующем размещении сравнить Secure Cloud и другой дата-центр.
5. Для постоянной работы заранее синхронизировать модели из ближайшего Object Storage.

### Закончилось место

Проверить каталоги:

```bash
du -h -d 1 /workspace | sort -h
df -h /workspace
df -h /
```

Не удалять неизвестные файлы до резервного копирования. В первую очередь проверить старые результаты, временные загрузки и кэши.

## План резервного копирования

До удаления рабочего Pod необходимо сохранить:

```text
/workspace/models
/workspace/user
/workspace/custom_nodes
/workspace/output
```

После подключения Object Storage процедура должна состоять из двух команд или скриптов:

1. `restore-workspace` — скачать отсутствующие модели, настройки и ноды перед работой;
2. `backup-workspace` — отправить изменённые workflow, настройки и результаты после работы.

Модели следует копировать на локальный Volume до генерации. Не запускать тяжёлые модели непосредственно через сетевое файловое монтирование без отдельного теста производительности.

## Контрольный тест переносимости

Считать систему готовой можно только после следующей проверки:

1. Сохранить рабочий `/workspace` во внешнее хранилище.
2. Создать новый Pod с пустым Volume.
3. Восстановить нужные каталоги.
4. Открыть сохранённый workflow.
5. Выполнить ту же генерацию.
6. Сверить результат и список загруженных нод.
7. Только после этого удалить старый Pod.
