# Повторный запуск Timesaver ComfyUI в RunPod

Схема: свой Docker-образ с ComfyUI, встроенным Manager и тремя TS-паками;
Network Volume с моделями, дополнительными нодами, workflow и результатами.
После подключения того же диска данные доступны новому Pod без восстановления
из резервной копии. Первый запуск всё ещё требует загрузки образа и моделей.

## Настройки шаблона

Сохранить собственный шаблон `Timesaver ComfyUI` со следующими полями:

| Поле | Значение |
| --- | --- |
| Container image | `ghcr.io/alexyez/timesaver-comfyui-docker:cu128` |
| Container Disk | 50 GB |
| Volume Disk | 0 GB, при размещении подключить Network Volume |
| Volume mount path | `/workspace` |
| HTTP port | `8188` |
| Port label | `ComfyUI` |
| Start command | Пустое поле: запуск выполняет ENTRYPOINT образа |

Переменные: `COMFY_DATA_DIR=/workspace`, `COMFY_PORT=8188`,
`REQUIRE_PERSISTENT_MOUNT=1`, `INSTALL_CUSTOM_NODE_REQUIREMENTS=1`.
Их значения сохранены в [template-settings.json](../runpod/template-settings.json).
Этот JSON — памятка для настройки и автоматизации, не файл импорта консоли.
Jupyter и SSH образ не запускает; портов 8888 и 22 в шаблоне нет.

Для рабочего шаблона после проверки выбрать digest образа `@sha256:…`, чтобы
еженедельная сборка не меняла окружение незаметно. Тег `cu128` использовать
для проверки обновлений. Конкретный рабочий digest ещё не выбран.

## Постоянный диск

Начать с Standard Network Volume на 150 GB: по текущему тарифу $10.50 в месяц.
Размер можно увеличить; уменьшить его нельзя. Сначала проверить наличие нескольких
подходящих GPU в дата-центре, затем создавать диск. Network Volume доступен
для Pods в Secure Cloud и ограничивает выбор GPU своим дата-центром.

Все модели, которые загружаются в `/workspace/models` или стандартный кэш
Hugging Face/Torch, сохраняются. Нода со своим путём загрузки вне `/workspace`
требует отдельной настройки. Кэш Hugging Face может хранить ещё одну копию
модели рядом с файлом в `models`; учитывать это в объёме диска.

## Ежедневная работа

1. Разместить Pod из своего шаблона и подключить тот же Network Volume.
2. Дождаться запуска приложения и открыть `ComfyUI` на порту 8188.
3. Открыть сохранённый workflow и запустить генерацию.
4. По окончании сохранить результаты, завершить Pod через Terminate и оставить
   Network Volume. Проверить прекращение GPU-тарификации в консоли.

Это запуск без ручных команд в терминале. Создание Pod и открытие интерфейса
остаются отдельными действиями. Для буквального запуска одной кнопкой понадобится
дополнительный launcher через RunPod API с выбранным диском и списком GPU.
Он пока не реализован. Доступность GPU и время скачивания образа не гарантированы.

## Ноды и обновления

На пустом диске три TS-пака копируются из образа. При следующих стартах их
каталоги сохраняются, включая обновления через Manager. ComfyUI и Manager
берутся из выбранного Docker-образа. Пересборка образа обновляет начальные версии
паков; уже существующие паки обновлять через Manager отдельно.

Зависимости дополнительных нод из `requirements.txt` восстанавливаются при старте.
Пакеты находятся в контейнере, скачанные дистрибутивы — в постоянном pip-кэше.
Особые установщики, `install.py` и системные библиотеки так не восстанавливаются:
такие ноды нужно включать в сборку. Для стабильного запуска часто используемые
дополнительные паки добавлять в `custom-nodes.txt` и проверять сборку.

Не обновлять ноды посреди рабочего рендера. Перед обновлением сохранять workflow
и резервную копию пользовательских данных. Сам Network Volume не заменяет backup.

## Проверка перед использованием

На одном тестовом Pod скачать небольшую модель, сохранить workflow и выполнить
генерацию. Завершить Pod и создать другой с тем же диском. Убедиться, что модель
не скачивается заново, workflow доступен и генерация проходит. Проверить также
одну установленную через Manager ноду после пересоздания контейнера.

5 октября локальный образ собран и проверен на RTX 3080 Ti Laptop GPU:
ComfyUI 0.38.0 отвечает, Manager 4.2.2 включён, все три TS-пака загружены,
`pip check` прошёл и вычисления CUDA работают. Пересоздание тестового контейнера
с тем же Docker Volume сохранило контрольные файлы в models, user и TS-паке.
Скрипт проверки запуска: [smoke-entrypoint.sh](../tests/smoke-entrypoint.sh).

Генерация с реальными моделями и размещение новой сборки в RunPod ещё не проверены.
ComfyUI выводит предупреждение о cu130 для оптимизированных CUDA-операций;
это не помешало запуску и тестовому вычислению с cu128. Образ пока опубликован
не был: локальный тег `timesaver-comfyui:local-test` нельзя указать в RunPod.

Источники: [Network volumes](https://docs.runpod.io/storage/network-volumes),
[Pod templates](https://docs.runpod.io/pods/templates/manage-templates).
